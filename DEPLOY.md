## 1. GitHub — create the repo, then push

1. On github.com create an **empty public** repository
   `Gautam825406/teachnest` — no README, no .gitignore, no licence
   (so it stays empty for the snapshot push).
2. Regenerate the push manifest and push the snapshot:

```bash
cd ~/workspace/teachnest && find . -type f \
  -not -path './frontend/node_modules/*' \
  -not -path './frontend/.next/*' \
  -not -path './backend/.venv/*' \
  -not -path './backend/.pytest_cache/*' \
  -not -path '*__pycache__*' \
  -not -name 'app.db' \
  -not -name '.env' -not -name '.env.local' \
  -print0 | sed -z 's|^\./||' > /tmp/teachnest-push-manifest

/opt/hatch/bin/github push-files --owner Gautam825406 --repo teachnest \
  --branch main --message "TeachNest Phase 1: multi-tenant admin panel (Next.js + FastAPI)" \
  --source-dir ~/workspace/teachnest --paths-file /tmp/teachnest-push-manifest
```

3. Confirm the repo shows the commit at
   https://github.com/Gautam825406/teachnest and record the commit SHA.

## 2. Render — backend (FastAPI)

No Render API key is available to the agent, so create it in the dashboard:

1. Render Dashboard → New → **Blueprint** → connect the `teachnest` repo
   (the `render.yaml` at the repo root defines the service), or
   New → Web Service with: root directory `backend/`,
   build `pip install -r requirements.txt`,
   start `uvicorn app.main:app --host 0.0.0.0 --port $PORT`, Python 3.12,
   plan Free.
2. Env vars: `SECRET_KEY` (Render generates it via the blueprint, or set a
   strong random value), `FRONTEND_ORIGIN` = the live Vercel URL
   (currently `https://teachnest.vercel.app` in `render.yaml` — update it
   in the Render dashboard if the real Vercel URL differs, then redeploy).
3. Wait for deploy, then verify:
   `curl https://<render-service>.onrender.com/api/health`
   → `{"status":"ok"}` (first request can take ~50 s on the free tier —
   the service sleeps when idle).

Live backend uses **SQLite on the service's ephemeral filesystem**: the DB
is created and demo-seeded on every start, so demo data is always there,
but anything created in the live demo is lost on restart/redeploy.
Switch to Render Postgres for persistent data (set `DATABASE_URL`).

## Known live limitations

- Render free tier sleeps after ~15 min idle — first request is slow.
- SQLite is ephemeral on Render (see Step 2).
- Cashfree is the payment provider (Phase 4). Set `CASHFREE_APP_ID`, `CASHFREE_SECRET_KEY`, `CASHFREE_ENV` in the Render dashboard and register the webhook `https://<render-service>.onrender.com/api/payments/cashfree/webhook` in the Cashfree dashboard; until then payments report "Cashfree not configured".
- File uploads store only the filename in Phase 1.
- Full browser click-through was not verified by the build agent.
